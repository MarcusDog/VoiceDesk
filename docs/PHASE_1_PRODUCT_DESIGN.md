# VoiceDesk 第一阶段产品设计

版本：v0.1
阶段：可交互原型
目标平台：Windows 11 x64

> 本文保留阶段一原型的历史验收口径。当前真实实现与 24 项蓝图完成度以 [完整蓝图实现状态](IMPLEMENTATION_STATUS.md) 为准。

## 1. 产品结论

VoiceDesk 不是单一的“语音转文字工具”，而是本地优先的声音知识工作台。核心资产链路固定为：

`Audio → Raw Transcript → Clean Transcript → Structured Notes → Draft`

阶段一只验证三个最高风险假设：

1. 用户能否在不理解模型术语的情况下完成“导入/录音 → 转写 → 编辑”。
2. 原始转写、AI 整理和创作文档是否能被清晰区分。
3. 三栏结构能否同时承载内容、播放和 AI 操作，而不让 AI 助手喧宾夺主。

## 3. 信息架构

一级导航保持为：首页、新建转写、全部记录、录音、AI 文档。设置放在侧栏底部，搜索和命令统一进入 `Ctrl + K`。

项目工作区内只保留三层内容：

- 转写：与音频逐段对应，可编辑但不被 AI 静默覆盖。
- 笔记：用户手写或从转写摘录的内容。
- 草稿：AI 生成或用户继续写作的内容。

## 4. 设计系统

### 设计气质

Calm、Precise、Private、Focused。采用 Windows 11 原生感与克制圆角，不使用高饱和霓虹或大面积装饰性渐变。

### 核心 token

- 主色：`#146EF5`
- 主文本：`#101A31`
- 次文本：`#6B7892`
- 分隔线：`#DFE7F1`
- 成功：`#16A36A`
- 警告：`#ED971C`
- 危险：`#EF4458`
- 控件圆角：8–10 px
- 卡片圆角：12–16 px
- 大面板圆角：18–20 px
- 主要控件高度：38–44 px

### 层级

常驻卡片用边界和表面色分层，不使用大阴影。阴影只用于命令面板、菜单、浮层和模态框。

### 动效与可访问性

- 普通过渡 150–220 ms。
- 支持 `prefers-reduced-motion`。
- 所有 icon-only 按钮提供可访问名称。
- 键盘焦点采用可见的 2 px 蓝色外框。
- 颜色不作为状态的唯一表达。

## 5. 关键交互

### 新建转写

文件进入前端队列后，仅显示“已添加”。正式版本必须在 Rust Core 完成格式、时长、磁盘空间与重复文件校验后才能进入任务队列。

### 录音

状态机：`IDLE → RECORDING ↔ PAUSED → FINALIZING → SAVED/FAILED`。当前原型实现前三个状态并以工作区代替完成页。

### 转写与 AI

原始转写永远不可被 AI 结果直接覆盖。AI 生成内容需要存储 `source_segment_ids`，界面中的时间点可跳回对应音频。

### 响应式规则

- ≥ 1180 px：三栏。
- 920–1179 px：窄侧栏 + 内容 + 窄 AI 面板。
- 701–919 px：窄侧栏 + 内容，AI 面板隐藏。
- ≤ 700 px：底部主导航，单栏内容。

## 6. 阶段一退出条件

- 主要页面可从侧栏互相到达。
- 导入、录音、打开项目和命令面板形成可演示闭环。
- 1440×900、1024×768 和窄屏布局无阻断性溢出。
- TypeScript 检查与 Vite 生产构建通过。
- 未实现的真实能力有清晰边界，不误导为已经接通。

## 7. 下一阶段架构约束

- UI：React + TypeScript，禁止直接调用 Python。
- Desktop Core：Tauri 2 + Rust，统一管理数据库、任务、媒体、模型和 sidecar。
- ASR Engine：Python sidecar，按 chunk 输出增量结果。
- LLM Engine：独立服务协议，生成内容必须携带来源 segment ID。
- 数据库：SQLite，长任务每个 chunk 完成后立即持久化，支持断点恢复。
